# BlockVote-India: Project File Structure

This document provides a comprehensive overview of the `BlockVote-India` repository. It explains how the project is organized and the purpose of each directory and key file.

## Root Directory

The root of the project contains the main orchestrators, documentation, and the foundational architecture of the four main modules (Frontend, Backend, ML Service, Blockchain).

```text
BlockVote-India/
│
├── frontend/                 # [Module 1 & 2 & 3] Flutter application (UI)
├── backend/                  # [Module 2] Django backend (Relayer & APIs)
├── ml_service/               # [Module 2] FastAPI microservice (Active Sentinel)
├── blockchain/               # [Module 1 & 3] Hardhat & ZKP project
│
├── docker-compose.yml        # Orchestrates local PostgreSQL and Redis containers
├── requirements.txt          # Unified Python dependencies (Django & FastAPI)
├── HARDWARE_REQUIREMENTS.md  # Minimum/Recommended specs to run the project locally
├── Project_Plan.md           # Step-by-step development roadmap
├── Project_Plan.txt          # Plaintext version of the project plan
├── FILE_STRUCTURE.md         # This document
└── .gitignore                # Global git ignore rules
```

---

## 1. Frontend (`/frontend`)
This directory contains the cross-platform Flutter application. It serves as the interface for the **Voter (Citizen Portal)**, **Administrator (Election Commission)**, and **Auditor (Independent Observer)**.

```text
frontend/
├── lib/                      # Main Dart source code
│   ├── main.dart             # Entry point of the Flutter application
│   ├── screens/              # UI pages (e.g., VotingBooth, AdminDashboard, Auth)
│   ├── widgets/              # Reusable UI components
│   ├── services/             # API clients, WebSocket listeners, Web3 integrations
│   └── utils/                # Helper functions (e.g., ZKP generator wrappers)
├── android/                  # Native Android project files
├── ios/                      # Native iOS project files
├── web/                      # Native Web project files
├── pubspec.yaml              # Flutter dependencies and asset declarations
└── analysis_options.yaml     # Dart linting and formatting rules
```

---

## 2. Backend (`/backend`)
This directory contains the Django application. It is responsible for handling Identity/KYC, WebSockets (for 3-minute secure QR sessions), and acting as the **Gasless Relayer** for blockchain transactions.

```text
backend/
├── config/                   # Main Django project configuration folder
│   ├── settings.py           # Database, apps, and Channels/Redis configurations
│   ├── urls.py               # Main URL router
│   ├── asgi.py               # ASGI config for WebSockets (Django Channels/Daphne)
│   └── wsgi.py               # WSGI config for standard HTTP requests
├── manage.py                 # Django CLI utility for running servers and migrations
└── venv/                     # Python virtual environment (ignored in git)
```
*(Note: As development progresses, new Django apps like `voters/`, `elections/`, and `relayer/` will be generated inside this folder).*

---

## 3. Machine Learning Service (`/ml_service`)
This directory contains a lightweight Python FastAPI microservice. It acts as an **Active Sentinel**, running an Isolation Forest model (via Scikit-Learn) to analyze relayer network traffic and thwart DDoS/botnet attacks.

```text
ml_service/
├── main.py                   # FastAPI application entry point (Inference API)
├── model.pkl                 # Pre-trained Scikit-Learn Isolation Forest model (To be generated)
├── train.py                  # Script used to train/retrain the ML model
└── venv/                     # Python virtual environment (ignored in git)
```

---

## 4. Blockchain & Cryptography (`/blockchain`)
This directory contains the Hardhat environment for Ethereum/Polygon smart contract development and the Circom environment for Zero-Knowledge Proof (zk-SNARK) circuits.

```text
blockchain/
├── contracts/                # Solidity source files
│   ├── ElectionRegistration.sol # Manages the Merkle root and voter whitelists
│   ├── Voting.sol               # Handles tallying and zk-SNARK verification
│   └── verifier.sol             # Auto-generated by SnarkJS to verify proofs on-chain
├── circuits/                 # Circom source files for Zero-Knowledge Proofs
│   ├── voter_eligibility.circom # Circuit proving Merkle tree inclusion & generating nullifier
│   └── build/                   # Compiled circuit keys (.wasm, .zkey, .vkey)
├── scripts/                  # Deployment scripts
│   └── deploy.js             # Script to deploy contracts to the Polygon Amoy network
├── test/                     # Hardhat test suites
│   ├── voting-test.js        # Unit tests for voting logic and proof verification
│   └── relayer-test.js       # Unit tests for Gasless Meta-Transactions
├── hardhat.config.js         # Hardhat configuration (Networks, Solidity version)
├── package.json              # Node.js dependencies (OpenZeppelin, Circomlib, SnarkJS)
└── package-lock.json         # Locked dependency tree
```
