# BlockVote-India: Master Development & Launch Plan

## Project Overview
**BlockVote-India** is a Zero-Trust Hybrid E-Voting Platform resolving the fundamental trilemma of voter privacy, legal eligibility, and tally immutability. It achieves this using client-side **zk-SNARKs** (Groth16) on the **Polygon blockchain**, **Gasless Meta-Transactions** via a Django Relayer, **AI-Driven Threat Mitigation** (Active Sentinel), and a flagship **Antigravity Light-Theme** user interface.

## Detailed Development Phases & Implementations

### Phase 1: Smart Contract & Cryptography Engine (Blockchain)
**Focus:** Core voting logic, zero-knowledge circuits, and security constraints on Polygon.
- [x] **ZKP Circuit Design (Circom):**
  - Poseidon Merkle tree inclusion circuit (`voter_eligibility.circom`) proving that a voter's secret commitment exists in the 20-level registered tree without revealing the identity.
  - Outputs a deterministic `nullifier` scalar preventing double-voting.
  - Exported proving artifacts: `voter_eligibility.wasm`, `voter_eligibility_final.zkey`, and `verification_key.json`.
- [x] **Smart Contracts (Solidity):**
  - `ElectionRegistration.sol`: Stores the whitelisted Merkle root with an immutable admin lock mechanism (`lockMerkleRoot`).
  - `Voting.sol`: Integrates the pairing verifier contract generated by SnarkJS (`verifier.sol`), checks proofs, records spent nullifiers, and increments candidate tallies.
- [x] **Testing & Validation:**
  - Automated Hardhat test suites for proof validation, double-voting rejection, and gas usage profiling.

---

### Phase 2: Core Backend System & Gasless Relayer (Django)
**Focus:** Centralized API, session security, dynamic OTP authentication, and gasless transaction relaying.
- [x] **Database Schema & Zero-Knowledge Models:**
  - `Election`: Manages timestamps, title, and on-chain Merkle root lock status.
  - `Candidate`: Stores candidate names, ballot IDs, parties, and symbols.
  - `VoterIdentity`: Zero raw PII storage. Stores only salted cryptographic SHA-256 hashes (`voter_hash = SHA256(EPIC + Mobile + Salt)`).
  - `BallotRecord`: Stores candidate selection, transaction hash, block number, gas used, and spent nullifier for auditor tracking.
  - `ThreatLog`: Logs anomalous requests rejected by the Active Sentinel AI.
- [x] **Dynamic OTP Authentication Flow:**
  - `/api/v1/send-otp/`: Generates cryptographically secure 6-digit OTPs with a 10-minute validity window.
  - **Dynamic Registration:** Requires citizen to enter Full Name, EPIC, Mobile, receive dynamic OTP, and verify before whitelisting.
  - **Dynamic Login:** Validates EPIC + Mobile + single-use OTP, verifies whitelisted status, and authorizes session.
- [x] **1-Minute Single-Use Cryptographic QR Sessions:**
  - `/ws/qr-session/`: Streams HMAC-SHA256 signed session tokens via WebSockets with an exact **60-second** lifetime.
  - **Auto-Disable & Lock:** At `00:00`, the QR code canvas displays an expired overlay and ballot submission buttons are disabled until the page is refreshed.
- [x] **Gasless Relayer (`/api/v1/relayer/submit-vote/`):**
  - Intercepts client proofs, checks Active Sentinel threat score, checks registry status, verifies nullifier anti-replay, signs via server gas wallet, and broadcasts to Polygon.

### Phase 3: Active Sentinel AI Microservice (FastAPI)
**Focus:** Autonomous machine learning firewall safeguarding the gasless relayer against DDoS and botnet attacks.
- [x] **Synthetic Telemetry Pipeline (`train.py`):**
  - Generated realistic network telemetry modeling legitimate citizen submissions vs. high-frequency DDoS floods (>30 req/sec) and payload stuffing attacks.
- [x] **Model Architecture:**
  - Trained `IsolationForest` (100 estimators, 5% contamination threshold) saved to `model.pkl`.
- [x] **High-Speed Inference Endpoint (`main.py`):**
  - Serves `POST /api/v1/analyze-threat/` in under 15ms. Returns `is_anomalous: true/false`, `threat_score`, and action recommendation (`BLOCK` or `ALLOW`).

## Demonstration Checklist for Judges & Evaluators

1. **Portal Selection:**
   - Navigate to `http://127.0.0.1:8000/`. Observe the three portal cards with clean status badges and Web3 wallet connectivity.
2. **Citizen Registration & Dynamic OTP:**
   - Navigate to `/auth/voter/?tab=register`.
   - Enter Citizen Name, valid EPIC (e.g., `IND7788990`), and Mobile (e.g., `9537690500` or any 10-digit number).
   - Click **Send Verification OTP to Mobile**.
   - Observe live SMS dispatched to registered mobile (and evaluation code in banner).
   - Enter the 6-digit code and submit. Citizen identity is registered and whitelisted.
3. **Citizen Login & Voting Booth:**
   - Form pre-fills credentials on the Login tab.
   - Click **Send OTP to Mobile**, enter the received code, and enter the terminal.
   - Observe **Step 2 (Dynamic QR)**: The 60-second single-use session countdown begins.
   - Select a candidate (e.g., Dr. A. Sharma) and click **Cast Anonymous Vote**.
   - Observe client-side proof generation modal, relayer broadcast, and Polygon transaction receipt with cryptographic nullifier.
4. **Session Expiry & Anti-Coercion Demonstration:**
   - Wait for the 60-second timer to reach `00:00`.
   - Notice the QR canvas changes to a red **Session Expired** overlay and the vote buttons are automatically disabled.
5. **Auditor Portal & Double-Voting Prevention:**
   - Navigate to `/auditor/`. View the newly broadcast transaction in the live mempool stream.
   - Attempt to vote a second time with the same credentials or nullifier -> System rejects with HTTP 409 Double Voting Conflict.
